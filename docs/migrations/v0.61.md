# v0.61

*Upgrading from*: v0.60.*

## What changed from v0.60.*

v0.61 removes the separate `github.com/grafana/grafana-app-sdk/plugin` Go module, along with the older plugin backend code
that the plugin v3 packages replace ([grafana-app-sdk#1637](https://github.com/grafana/grafana-app-sdk/pull/1637)):

1. The packages under `plugin/` are now part of the main `github.com/grafana/grafana-app-sdk` module. Their import paths don't change.
2. The `plugin/router` and `plugin/kubeconfig` packages, and the error helpers in `plugin` (`plugin.Error`, `NewError`, `WrapError`,
   `FromError`, `InternalError`, `NotFoundError`, `BadRequestError` and `MarshalError`), are removed.
3. The CLI's `project component add backend` command is removed, along with the `pkg/plugin` and `plugin/pkg` code it generated.
4. The `cmd/operator/kubeconfig.go` generated by `project component add operator` no longer imports `plugin/kubeconfig`.

The experimental plugin protocol v3 `ConvertObjectsRequest` also changed in this release
([grafana-app-sdk#1636](https://github.com/grafana/grafana-app-sdk/pull/1636)). See [Plugin protocol v3 conversion](#plugin-protocol-v3-conversion).

## The `plugin` module is now part of the main module

> [!WARNING]
> No `plugin/v0.61.*` tag is published. Remove `github.com/grafana/grafana-app-sdk/plugin` from your `go.mod` when you upgrade.
> If your build still pulls in a v0.60 or earlier version of that module, Go fails with an error like this:
> ```
> github.com/grafana/grafana-app-sdk/plugin: ambiguous import: found package github.com/grafana/grafana-app-sdk/plugin in multiple modules:
> 	github.com/grafana/grafana-app-sdk v0.61.0 (...)
> 	github.com/grafana/grafana-app-sdk/plugin v0.60.17 (...)
> ```
> This happens because both modules provide the same packages.

Your imports, such as `github.com/grafana/grafana-app-sdk/plugin` and `github.com/grafana/grafana-app-sdk/plugin/appadapter`, stay the same. Only `go.mod` changes:

```bash
go mod edit -droprequire github.com/grafana/grafana-app-sdk/plugin
go get github.com/grafana/grafana-app-sdk@v0.61.0
go mod tidy
```

Also remove any `replace` directive for `github.com/grafana/grafana-app-sdk/plugin`.

If you still get the ambiguous import error after that, another dependency requires the old module. To find it, run:

```bash
go mod graph | grep 'grafana-app-sdk/plugin@'
```

Then upgrade that dependency to a version built on grafana-app-sdk v0.61 or later.

## Removed `plugin/router` and `plugin/kubeconfig`

> [!WARNING]
> Code that imports `github.com/grafana/grafana-app-sdk/plugin/router` or `github.com/grafana/grafana-app-sdk/plugin/kubeconfig`
> won't compile with v0.61. That includes the `pkg/plugin` and `plugin/pkg` code generated by `project component add backend`.

These packages implemented a plugin backend that proxied CRUDL requests to the API server, through grafana's plugin resource API
(`/api/plugins/<plugin-id>/resources/...`). It read a kube config from the plugin's `secureJsonData`. The replacements are:

* **For CRUDL requests from your frontend:** call the API server directly at `/apis/<group>/<version>/namespaces/<namespace>/<plural>`.
  The generated TypeScript types work with these endpoints. The [issue tracker tutorial](../tutorials/issue-tracker/06-frontend.md) shows an example.
* **For non-CRUD endpoints:** define custom routes on your kinds (see [Applications with Custom APIs](../application-design/README.md#applications-with-custom-apis)), and implement them in your `app.App`.
* **To run your app inside a plugin backend:** use `plugin.Run` with your `app.Provider`. It builds the kube config from the environment
  (`plugin.BuildKubeConfig` or `plugin.BuildKubeConfigWithOptions`) instead of from `secureJsonData`. See the
  [plugin protocol v3 example](../../examples/plugin/README.md), and [example-appsdktest-app](https://github.com/grafana/app-examples/tree/main/example-appsdktest-app)
  for a complete plugin.

> [!CAUTION]
> Plugin protocol v3 is experimental. Its Go APIs and wire format may change in any release, as they do in this one.

If you can't migrate yet, keep using grafana-app-sdk v0.60.*. You can also copy the packages you use from the
[v0.60.17 source](https://github.com/grafana/grafana-app-sdk/tree/v0.60.17/plugin) into your own module, but they no longer get fixes.

## Removed `project component add backend`

`grafana-app-sdk project component add backend` now fails with `unknown component backend`. The `frontend` and `operator`
components are unchanged. Remove `backend` from any scripts that call `project component add`, for example:

```bash
# Before
grafana-app-sdk project component add frontend backend operator
# After
grafana-app-sdk project component add frontend operator
```

Code that this command generated earlier isn't removed from your project, but it won't compile (see the warning above).
You can delete `pkg/plugin`, `plugin/pkg` and `plugin/Magefile.go`, and then set `"backend": false` and remove `"executable"` in `plugin/src/plugin.json`.
The Makefile generated by `project init` skips the backend build when there is no `plugin/Magefile.go`.

## Operator `kubeconfig.go`

> [!IMPORTANT]
> Boilerplate is generated once and not regenerated by `grafana-app-sdk generate`, so the change to `cmd/operator/kubeconfig.go` doesn't apply to existing projects.
> If your project was created with `project component add operator`, its `cmd/operator/kubeconfig.go` imports `plugin/kubeconfig` and won't compile with v0.61.

Update `cmd/operator/kubeconfig.go` to return a `*rest.Config`:

```go
package main

import (
	"k8s.io/client-go/rest"
)

// LoadInClusterConfig loads a kubernetes in-cluster config.
func LoadInClusterConfig() (*rest.Config, error) {
	cfg, err := rest.InClusterConfig()
	if err != nil {
		return nil, err
	}
	cfg.APIPath = "/apis"
	return cfg, nil
}
```

Then update where `cmd/operator/main.go` uses it:

```go
// Before
KubeConfig: kubeConfig.RestConfig,
// After
KubeConfig: *kubeConfig,
```

The old `NamespacedConfig` always set its namespace to `"default"`, and the generated operator never read it.
If your own code read `kubeConfig.Namespace`, replace it with your own namespace configuration.

## Plugin protocol v3 conversion

> [!WARNING]
> This changes the protobuf wire format and reassigns field numbers. Hosts and plugins must upgrade together.

`ConvertObjectsRequest` now has these fields:

* `target`, the full GroupVersionKind to convert to
* `namespace`
* `objects`, the raw JSON objects to convert

The old `api` and `target_version` fields, the per-object wrappers and the `RawObject` message are removed.
The source GroupVersionKind of each object is read from its `apiVersion` and `kind`.
Requests authenticated with tenant-scoped tokens must set `namespace`. An empty namespace requires a wildcard token.
See [grafana-app-sdk#1636](https://github.com/grafana/grafana-app-sdk/pull/1636) for details.

## Migration steps

1. Remove `github.com/grafana/grafana-app-sdk/plugin` from `go.mod`, along with any `replace` for it, and upgrade `github.com/grafana/grafana-app-sdk` to v0.61.
2. Run `go mod tidy`. If you get an ambiguous import error, find and upgrade the dependency that requires the old `plugin` module.
3. If you use `plugin/router`, `plugin/kubeconfig` or the `plugin` error helpers, including code generated by `project component add backend`,
   move to direct API server calls, custom routes or `plugin.Run`. You can also keep v0.60 until you're ready.
4. Remove `backend` from any `project component add` commands in your scripts.
5. If you have a generated `cmd/operator/kubeconfig.go`, update it and `cmd/operator/main.go` as shown above.
6. If you implement or call the plugin v3 conversion service, update your host and plugin together.
7. Run `go build ./...` and your tests.
